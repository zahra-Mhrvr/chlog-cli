# chlog

A little CLI that reads your git history and generates a `CHANGELOG.md`,
grouped by commit type (Features, Bug Fixes, Docs, etc). Built this after
manually writing changelogs for a side project one too many times and
realizing the information was already sitting right there in `git log`.

Works with [conventional commits](https://www.conventionalcommits.org/)
(`feat: `, `fix: `, `fix(scope): `, etc). Anything that doesn't match that
format still shows up, just under an "Other" section instead of being
silently dropped.

## Install

Not published to PyPI yet — clone it and install locally for now:

```bash
git clone <your-repo-url>
cd chlog-cli
pip install -e .
```

That gives you a `chlog` command on your PATH (thanks to the
`[project.scripts]` entry point in `pyproject.toml`).

## Usage

Preview without writing anything:

```bash
chlog preview
```

Generate a changelog for everything up to now:

```bash
chlog generate --version v1.0.0
```

Only include commits since your last release tag:

```bash
chlog generate --version v1.1.0 --since v1.0.0 --prepend
```

`--prepend` adds the new section to the top of an existing `CHANGELOG.md`
instead of overwriting the whole file. If you use `--prepend` without
`--since`, it'll warn you — otherwise every entry ends up containing your
entire history again, which took me a minute to notice the first time I
tried it.

Point it at a different repo:

```bash
chlog preview --repo ../some-other-project
```

## How it works

1. `chlog/parser.py` shells out to `git log --pretty=format:%H\x1f%s` and
   parses each subject line against a conventional-commit regex
2. `chlog/changelog.py` groups the parsed commits by type and renders
   markdown, in a fixed section order (Features and Bug Fixes float to the
   top since those are what people usually care about first)
3. `chlog/cli.py` wires it up with `click` — `preview` prints to stdout,
   `generate` writes to a file

## Tests

```bash
pip install -e ".[dev]"  # or just: pip install pytest
pytest tests/ -v
```

`tests/test_integration.py` actually creates a real git repo in a temp
directory, makes real commits, and runs `chlog` against it — since the
whole point of this tool is its relationship with real `git log` output,
mocking that felt like it'd be testing nothing.

## Known limitations

- No config file yet — the list of recognized commit types
  (`feat`, `fix`, `docs`, ...) is hardcoded in `parser.py`. Making that
  configurable would be the natural next step if I used this on a project
  with different conventions.
- Doesn't touch commit bodies at all right now, only the subject line — a
  `BREAKING CHANGE:` footer wouldn't be picked up, only a `!` right after
  the type/scope.
- Assumes a linear-ish history; hasn't been tested on a repo with a lot of
  merge commit noise beyond the `--no-merges` flag already filtering out
  merge commits themselves.
